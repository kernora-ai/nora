# Kernora — Architectural Decisions

> This file is automatically updated by Kernora as it captures architectural decisions from your sessions.
> Decisions include context, rationale, and alternatives considered.

## How Kernora Decisions Work

When you make architectural choices during coding sessions — picking a library, choosing a data structure, selecting an API design — Kernora captures the decision along with the context and rationale. This prevents your AI agent from relitigating settled decisions.

## Getting Started

As you code with Kiro, Kernora will record decisions here:

- Technology choices (frameworks, libraries, services)
- Architecture decisions (monolith vs microservice, sync vs async, SQL vs NoSQL)
- API design decisions (REST vs GraphQL, versioning strategy)
- Infrastructure decisions (hosting, CI/CD, monitoring)

## Decision Format

Each decision includes:
- **Decision summary**
- **Context** — what prompted the decision
- **Rationale** — why this choice was made
- **Alternatives considered** — what else was evaluated
- **Date** — when the decision was made
