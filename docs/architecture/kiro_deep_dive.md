# Deep Dive: AWS Kiro Integration Strategy

AWS Kiro represents a significant shift from "autocomplete AI" (like Copilot) to "Spec-Driven Autonomous Agents." Because Kiro operates actively as a co-developer parsing specifications before writing code, it offers Kernora the deepest integration hooks of any platform on the market.

Here is an architectural breakdown of exactly what Kiro is capable of, and how we can aggressively exploit those capabilities to embed Kernora's **Individual and Team Dashboards** directly *inside* the Kiro ecosystem.

---

## 1. Kiro CLI Interception (The Spec Guardrail)
**Core Capability:** "Spec-Driven Development." Kiro CLI parses a natural language prompt and converts it into a markdown "Implementation Specification." It natively surfaces "Agent Hooks."
**How Kernora Leverages This:**
*   **The Spec Checkpoint:** Instead of intercepting the user's raw, messy prompt (which is notoriously hard to parse programmatically), Kernora intercepts the **machine-generated Spec** using Kiro's `OnSpecGenerated` lifecycle hook. 
*   **The Execution:** You run `kiro "build an auth system"`. Kiro generates a 5-page markdown spec and triggers the hook. Kernora's Python CLI daemon reads the spec instantly. If the spec plans to introduce massive monolithic changes bypassing local architecture rules, Kernora halts the CLI process and explicitly outlines a safer, decomposed architecture path to the developer.

---

## 2. Kiro IDE Capabilities & Dashboard Embedding
**Core Capability:** Kiro is a full GUI desktop editor (built heavily on familiar Language Server Protocols and Model Context Protocol integrations). This means it physically supports **Webviews** and **Sidebar Custom UI Panels**.

### Can we build Individual and Team Dashboards INSIDE Kiro?
**Absolutely yes.** This is an architectural trump card. Developers despise context-switching (Alt-Tabbing out of their code editor to look at a browser metrics page). 

Because Kernora's dashboard is built as an independent React application running currently on `localhost:2742`, we don't have to rebuild it from scratch. We simply wrap the React application inside a **Kiro IDE UI Panel Webview**.

*   **The Individual Dashboard (In Kiro):** 
    *   We generate a native Kiro Extension. It adds a "Kernora Control Plane" icon to the Kiro sidebar.
    *   When clicked, it opens a Webview that renders `localhost:2742` natively inside the Kiro editor pane.
    *   The developer can instantly review their friction score, token burn rate, and AI looping errors right next to their codebase.
*   **The Team Dashboard (In Kiro):** 
    *   For Phase 1 (Enterprise/Team sync), Vice Presidents of Engineering or Staff Engineers using Kiro can open the "Team View" panel.
    *   The Webview securely pulls aggregated AWS S3 Litestream data into the Kiro panel, allowing the Staff Engineer to review the "Most Efficient AI Prompters" leaderboard or discover highly successful "Nora Distilled Skills" generated by teammates without ever leaving their IDE.

---

## 3. Model Context Protocol (MCP) Guardrails in Kiro
**Core Capability:** Kiro natively integrates local MCP servers into its agentic tool loop.
**How Kernora Leverages This:**
*   **The 'Pre-Flight' API:** By registering `kernora_mcp.py` dynamically into the Kiro settings, Kiro is forced to recognize Kernora as a foundational internal tool.
*   **AWS Infrastructure Awareness:** Since Kiro is built by AWS, it will natively suggest and build AWS infrastructure (Lambda, DynamoDB, API Gateways). Kernora exposes an MCP tool specifically targeting IaC: `kernora_aws_drift_check()`. When Kiro plans to spin up resources, it consults Kernora's MCP tool. Kernora scans the company security playbook and dynamically permits or denies Kiro from deploying insecure AWS components, returning a native UI rejection directly inside the Kiro chat feed.
