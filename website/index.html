Playbook

  1. Run the build command for the target platform using appropriate tools
  2. Diagnose build failures resulting from isolated git worktree environments
  3. Identify and copy missing gitignored config/secret files into the worktree
  4. Rebuild the project to ensure a clean compilation
  5. Commit approved changes, merge worktree branch into master, and push

Anti-Patterns

Testing a build in a new git worktree without ensuring gitignored files are synced.

Fix: Always check for .env, .plist, and secret files when initializing a new git worktree.

CLAUDE.md Rule Suggestions

Always verify the presence of GoogleService-Info.plist and other gitignored secret files when operating within a newly created git worktree.

Why we built this

Mihir Choudhary was deep in AI-assisted work — shipping products with Claude Code, orchestrating agents across Kiro and Cursor, managing teams where every engineer had a different AI workflow. Hundreds of sessions. Thousands of decisions. The same bugs kept recurring. The same patterns kept getting rediscovered across team members who never saw each other's sessions. The AI models kept getting smarter. The human knowledge kept evaporating.

Then came the harder question: how do you manage an agentic workforce? When developers work alongside AI agents — each with different capabilities, different context windows, different failure modes — the old metrics break. Lines of code, PRs merged, story points closed — none of them capture whether the team is actually getting better at working with AI, or just burning tokens.

Kernora exists to answer that question. Not just for the individual developer who wants to stop re-learning, but for the engineering manager who needs to see which AI patterns are spreading and which are failing silently, and for the CTO who needs to know whether AI adoption is compounding into real organizational capability or just generating noise.
